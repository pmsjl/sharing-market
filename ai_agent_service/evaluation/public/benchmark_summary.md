# Golden v1.3 Five-Stage Ablation

同一份评测数据（v1.3，200 题）、同一套评测脚本、同一固定索引。五个阶段中的每一个只在前一阶段基础上增加一项能力：阶段 1 为无 Router 基线，阶段 5 为当前正式版本。

| 阶段 | 相对前一阶段新增的唯一变量 |
|---|---|
| 阶段 1 | 无 Router 基线（原检索与原回答提示词） |
| 阶段 2 | 接入 LLM Router（检索规划与回答提示词不变） |
| 阶段 3 | 在 Router 基础上启用 ABC 三通道课程检索 |
| 阶段 4 | 加入短 chunk ID 映射（仅增加映射所需的引用协议） |
| 阶段 5 | 最终提示词优化（= 当前正式版本） |

> 本文的「阶段」指能力逐步叠加的对比版本，与运行流水线的 Router → Retrieval → Generation → Judge → Final 五个环节不是同一个概念。

## 数据来源与统计方法

完整 Golden v1.3 共 200 题，Dev 140 / Test 60；课程题 20，boundary 41、campus 30、platform 45、post 64。公开包只包含脱敏 Dev；五个阶段的变量叠加顺序见文首阶段说明。

排序指标统计期望 retrieve 且至少有一个 relevance ≥ 2 qrel 的 127 题。Hit@k 判断首个 relevance ≥ 2 的文档是否落在前 k 位。条件 Hit@k 仅统计实际进入检索的题；阶段 1 无 Router，因此 Router 准确率不适用。Final 沿用生成成功且 Judge overallPass 为真的判定标准。

固定索引：`20260819T151857Z-b1c54bb0e56f49e89251135abebc4c71`。

五阶段对比反映各阶段整体实现与提示词的效果。聚合指标覆盖完整 200 题（含 Test），公开 Dev 可复算其自身子集。
