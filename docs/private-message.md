# 校园私信：会话列表与全局抽屉

## 后端范围

只新增 `POST /api/privateMessage/my/conversation/list/page/vo`，复用现有 `private_message` 和 `user` 表，无数据库迁移。发送 `/api/privateMessage/add`、双人记录 `/api/privateMessage/my/list/page/vo` 保持原有契约。

请求：

```json
{ "current": 1, "pageSize": 20 }
```

当前用户来自登录态，不接收用户 ID。`current` 最小为 1，`pageSize` 非正数时使用 20、最大 100；结果固定按最近消息时间和消息 ID 倒序，不接受自定义排序。省略 pageSize 时沿用 PageRequest 默认值 10。

返回标准 `Result<Page<PrivateConversationVO>>`，每条记录包含：

| 字段 | 含义 |
| --- | --- |
| contactUserId | 对方用户 ID |
| userName / userAvatar | 对方昵称、头像 |
| lastMessageId | 最近一条双方消息 ID |
| lastMessageContent | 最近消息摘要，最多 120 个字符 |
| lastMessageTime | 最近消息时间 |
| lastReceivedMessageId | 对方发给当前用户的最大消息 ID；没有来信时为空 |

ID 沿用项目 Long → JSON 字符串规则。分页以联系人为单位，包含发送和接收两个方向；逻辑删除消息不参与聚合，无关用户的消息不进入结果。没有消息的临时联系人不写入服务器。

## 前端行为

- 登录后顶栏常驻消息入口；个人主页保留私聊入口。点击联系卖家或私聊作者直接打开右侧抽屉，保留当前页面；旧个人主页私聊链接仍兼容。
- 会话列表从后端恢复，按最近消息排序。管理员仍可使用原有用户列表接口查找同学并主动发起私聊。
- 页面可见时每 8 秒刷新会话，展开的聊天也刷新记录；隐藏页面暂停定时请求，回到页面立即同步，恢复网络立即刷新会话。退出登录清理定时器、内存会话和草稿，过期异步结果不能覆盖新会话。
- 新来信显示入口红点和会话“新消息”标记；不在当前会话时弹出 4 秒轻提示，多个通知合并为一个，无声音、不自动展开。
- 只有当前会话滚动到底部、消息已加载且页面可见时，才推进本机阅读位置。阅读旧消息时显示“有新消息，点击查看”。
- 阅读位置按账号保存在 `market:private-read:<userId>`，同浏览器标签页同步；首次加载以历史消息建立基线，不弹历史提醒。换设备或清除浏览器存储后无法恢复阅读进度，会话和记录仍由后端恢复。
- 聊天记录按需分页；消息 ID 始终按字符串 / BigInt 处理，避免精度丢失。发送失败保留草稿，中文输入法确认不误发送；发送中的联系人在关闭、重开抽屉后仍禁止重复提交。
- 不包含服务端已读数、跨设备阅读同步、WebSocket 或关闭网站后的系统推送。

## 验证

`PrivateConversationTest` 通过 H2 MySQL 模式执行真实 Mapper SQL，覆盖双向联系人、自己的回复与来信区分、隐私隔离、删除过滤、分页、排序和参数边界。H2 仅为测试依赖。

前端使用 `npm run lint`、`npm run build` 验证；浏览器配合模拟接口检查收发、通知、历史分页、阅读进度、失败重试、竞态、旧链接、退出清理和桌面 / 手机 / 夜间模式。模拟接口验证不等同于生产环境多账号联调。
